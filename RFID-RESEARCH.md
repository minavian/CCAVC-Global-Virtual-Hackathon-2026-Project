# RFID technology and development roadmap

## RFID fundamentals

Radio-frequency identification (RFID) uses radio signals to exchange data between a **reader** and a **tag**. A tag typically has an antenna and a chip. The reader collects a response, and software can associate that response with an item, record, or workflow. A **passive** tag draws operating power from the reader’s field. An **active** tag uses its own power source to transmit. A **battery-assisted passive** tag uses a battery for internal functions and relies on the reader’s signal for its backscatter reply. These designs suit different power, range, and maintenance needs. [NIST RFID overview](https://csrc.nist.gov/pubs/sp/800/98/final), [GS1 Gen2 standard, battery-assisted passive systems](https://ref.gs1.org/standards/gen2/3.0.1/)

| RFID family | Signal and common uses | Sources |
| --- | --- | --- |
| Low frequency (LF) | Examples operate at 125 or 134.2 kHz. Short-range inductive systems are used for applications such as vehicle immobilizers and animal identification. A vehicle fob may contain several radios for different functions. | [NIST RFID overview](https://csrc.nist.gov/pubs/sp/800/98/final), [TI 134.2 kHz immobilizer transponder](https://www.ti.com/product/TMS37145), [NXP keyless-entry chip](https://www.nxp.com/products/security-and-authentication/secure-car-access/passive-keyless-entry-chip%3ANCF29AG-H) |
| High frequency (HF) | 13.56 MHz systems include ISO/IEC 14443 proximity cards and ISO/IEC 15693 vicinity tags. NFC also uses 13.56 MHz and defines modes that include reading and writing tags and emulating cards. Common examples include contactless payments and tags that carry web links. | [ISO/IEC 14443-2](https://www.iso.org/standard/73597.html), [ISO/IEC 15693-2](https://www.iso.org/standard/73601.html), [NFC Forum technical overview](https://nfc-forum.org/learn/nfc-technology/) |
| Ultra-high frequency (UHF) | GS1’s passive Gen2 air interface spans 860–930 MHz. This family is used for tasks such as counting tagged stock or observing cartons at a dock door. Deployed readers use channels and power settings allowed in their region. | [GS1 Gen2 3.0.1](https://ref.gs1.org/standards/gen2/3.0.1/), [Auburn RFID Lab ARC benchmarking](https://rfid.auburn.edu/arc/about.php) |

A reader and tag need a shared air-interface protocol as well as a compatible frequency. The application also needs to understand the returned data. For example, a reader that supports ISO/IEC 14443 Type A can communicate with a compatible NFC Type 2 tag. ISO/IEC 15693 support is a separate capability even though both operate at 13.56 MHz. [NXP NTAG21x datasheet](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf), [NXP PN7160 supported protocols](https://www.nxp.com/products/PN7160)

### How passive tags get power and reply

**HF and NFC.** The reader coil produces an alternating magnetic field. When enough magnetic flux passes through the tag’s loop, it induces a voltage. The tag’s resonant circuit helps capture energy at the carrier frequency, and an on-chip rectifier supplies DC power. To reply, a passive HF tag switches its electrical load in a pattern the reader can detect through the coupled coils. This is called *load modulation*. Greater separation or misalignment can weaken coupling. Nearby metal can draw energy through eddy currents and detune the antenna. Ferrite can reduce these effects in designs made for metal mounting. NFC Forum Release 15 defines a 20 mm operating volume for compliance testing. Practical range depends on the reader, tag, alignment, and surroundings. [NXP NTAG21x datasheet, §8](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf), [NXP passive load modulation, §8.10.4](https://www.nxp.com/docs/en/data-sheet/PN7462.pdf), [NXP antenna design guide, §2](https://www.nxp.com/docs/en/application-note/AN11564.pdf), [NFC Forum specifications](https://nfc-forum.org/build/specifications/)

**Passive UHF Gen2.** The reader transmits a radio signal that powers tags in its read zone. A tag replies by changing how strongly its antenna reflects the signal, a technique called *backscatter*. To inventory many tags, the reader starts an inventory round and sends a parameter called Q. Each participating tag chooses a random slot from 2^Q possibilities. When two tags pick the same slot, their replies can overlap. The reader can adjust Q and continue inventorying. Antenna polarization, tag orientation, mounting material, and reflections affect which tags it sees, so evaluate the selected tag and reader on the actual item and in the intended location. [GS1 Gen2 3.0.1, §6.3 and Annex D](https://ref.gs1.org/standards/gen2/3.0.1/), [Auburn RFID Lab ARC benchmarking](https://rfid.auburn.edu/arc/about.php), [Cal Poly Gen2 pallet study](https://digitalcommons.calpoly.edu/it_fac/2/)

### Tag data and read events

- **A UID helps a reader identify or select a contactless chip.** Depending on the tag, the value can be stable, non-unique, or randomized. Treat it as an identifier. Applications that need to verify a credential use a separate authentication mechanism, and application policy determines whether to authorize an action. [NXP UID application note](https://www.nxp.com/docs/en/application-note/AN10927.pdf), [NIST RFID security guidance](https://csrc.nist.gov/pubs/sp/800/98/final)
- **An EPC identifies the object or entity associated with a tag.** A serialized EPC can identify an individual item. A UHF Gen2 tag also has a tag identifier (TID) memory bank that describes the tag IC and can include a chip serial number. For NFC tags, NDEF is a message format for payloads such as text or URLs. [GS1 EPC Tag Data Standard](https://ref.gs1.org/standards/tds/), [NFC Forum specifications](https://nfc-forum.org/build/specifications/)
- **A read records an observation.** A stationary reader can observe the same tag repeatedly, see a tag across a zone boundary, or miss an item passing through. Software can aggregate repeated observations and use a workflow to decide whether they represent a check-in, receipt, or other business event. GS1 EPCIS gives those events a shared format and distinguishes the observation location from the item’s expected business location afterward. [GS1 system architecture](https://ref-pd.gs1.org/architecture/system-architecture/), [GS1 EPCIS implementation guideline, §4.6.3](https://ref.gs1.org/guidelines/epcis-cbv/2.0.0/)

## RFID Field Lab development roadmap

**Current baseline.** In the landing-page branch, the browser workbench uses a shared chip-and-coil model with device-specific dimensions. A scan succeeds after a modeled object stays within a fixed distance threshold for 0.60 seconds. Those coordinates and timings are simulation parameters. The next milestone is a more accurate model of a single HF interaction, followed by bench measurements for a specified reader and tag. [Circuit model](https://github.com/minavian/CCAVC-Global-Virtual-Hackathon-2026-Project/blob/452d44d9d1e6cfb585c984c8e71b1bcdfc1aec18/src/models/circuit.js#L6), [workbench scan logic](https://github.com/minavian/CCAVC-Global-Virtual-Hackathon-2026-Project/blob/452d44d9d1e6cfb585c984c8e71b1bcdfc1aec18/src/lab/workbench.js#L266-L295)

### 1. Model a documented 13.56 MHz interaction

Use an NFC Type 2 tag as the reference. Show the reader’s field, power pickup at the tag loop, and the load-modulated response as separate stages. Give the simulation controls for separation, tilt, lateral offset, and a nearby metal surface. Use qualitative coupling until bench data supports using physical units. Add an incompatible-reader state so the interaction can fail even at close range. Validate an aligned read, a weak-coupling condition that fails to read, and a protocol mismatch using repeatable scenarios. [NXP NTAG21x datasheet](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf), [NXP antenna design guide](https://www.nxp.com/docs/en/application-note/AN11564.pdf)

### 2. Measure a real NFC reader and tag

Use one documented ISO/IEC 14443 Type A reader and compatible test tags such as NTAG213. One option is an MFRC522-based module already available to the team. Use a spacer or jig to set distance and angle. Start with a centered tag on a nonconductive mount. Repeat with increased gap, then with tilt, then with metal behind the tag, changing one variable at a time. Return the tag outside the read zone before each trial. A starting protocol is 20 attempts per condition with a one-second window. Record successful attempts, missed attempts, and time to first successful read. Save the raw results alongside the reader model and firmware, tag model, mounting surface, distance, and angle. Use the observed success rate and timing to calibrate the corresponding simulation scenario. Label the hardware configuration behind the measurements. [NXP MFRC522 datasheet](https://www.nxp.com/docs/en/data-sheet/MFRC522.pdf), [NXP NTAG21x datasheet](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf)

### 3. Connect bench hardware to the browser

Have the reader or its host microcontroller send timestamped read observations over a serial connection. Feed those events into the existing workbench display with a visible distinction between simulated and measured observations. Include the reader, protocol, test tag ID, and timestamp. Use a timed scan to distinguish a read timeout from a disconnected reader. Check consecutive taps, repeated reads from a tag left in the field, and reconnecting after an unplug. Test Web Serial on a supported browser. For a phone-only experiment, Web NFC on Chrome for Android can read NDEF payloads from compatible tags. Each approach can be tested with synthetic IDs and sample payloads. [Chrome Web Serial](https://developer.chrome.com/docs/capabilities/serial), [Chrome Web NFC](https://developer.chrome.com/docs/capabilities/nfc)

### 4. Add UHF inventory as a separate experiment

Build a simulation of Gen2 inventory slots so the results show empty slots, successful replies, and collisions as tag count and Q change. If physical UHF hardware is available, document the reader’s regional configuration and test a known group of labeled items. Keep nearby tagged items outside the intended zone to measure unintended reads. Record the fraction of expected tags captured, the number of out-of-zone tags observed, and the elapsed time per pass. If resulting business events need to be shared across systems, evaluate EPCIS after the application can reliably turn reader observations into inventory events. [GS1 Gen2 3.0.1](https://ref.gs1.org/standards/gen2/3.0.1/), [Auburn RFID Lab ARC benchmarking](https://rfid.auburn.edu/arc/about.php), [GS1 EPCIS implementation guideline](https://ref.gs1.org/guidelines/epcis-cbv/2.0.0/)
